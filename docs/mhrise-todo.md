# モンハンライズ クエストテーブル推測 やることリスト

目的: クエストごとのフィールド（大社跡・寒冷群島・溶岩洞）と当否の記録から、
滞在テーブル（テーブルA・テーブルB・天国準備・天国）を推測する画面を、自分で作れるようになる。

出典: なな徹「クエストテーブル」解析 https://nana-press.com/kaiseki/machine/837/25362/

進め方のルール（CLAUDE.md より）

- ロジックは純粋関数か hook に切り出し、**先にテストを書いて失敗を確認してから**実装する
- テストは「表示されている」ではなく「値が○○になる」を確かめる
- 終わったら `npm run check` を通す

---

## 0. 仕様を自分の言葉で書く

- [ ] 出典ページを読み、次の3種類の表がそれぞれ何を表しているか説明できる
  - クエスト回数別の**成功期待度**（テーブルごと）
  - **フェイク前兆**のときのフィールド選択率（テーブルごと・回数ごと）
  - **本前兆**のときのフィールド選択率（テーブルごと・回数ごと）
- [ ] 「成功期待度」は「その回まで来たときに、その回で当たる確率」なのか、「最初から見てその回で当たる確率」なのかを考え、理由を書く（ヒント: 7回目が 100%）
- [ ] 天国の表が1回目しか無い理由を説明できる
- [ ] 7回目のフェイク前兆が「-」になっている理由を説明できる
- [ ] ユーザーが画面で入力するもの・画面に出すものを箇条書きにする

## 1. 確率の計算を紙（またはメモ）でやる

- [ ] 1つのテーブルについて、「1回目 大社跡で外れ → 2回目 寒冷群島で当たり」になる確率を式で書く
  - 各回で「当たる/外れる確率」と「フィールドの選択率」の両方が要ることを確認する
- [ ] 同じ記録について、4テーブルぶんの値を計算する（電卓や Python で可）
- [ ] 4つの値を「合計が 100% になるように」割り振る。なぜ割り振ってよいのか（事前確率を均等とする前提）を説明できる
- [ ] 「結果待ち（当たりか外れかまだ分からない）」の回は、どう計算すればよいか考える
- [ ] あり得ない記録（例: 7回目で外れ、天国で1回目に外れ）のとき、各値がどうなるか確認する
- [ ] ここで出した数値をメモしておく → 2 のテストの期待値に使う

## 2. ロジック（純粋関数）をテストから作る

置き場所: `src/machines/mhrise/`

- [ ] 出典の数値を定数にする。意味をコメントで残す（CLAUDE.md の規約）
  - どんなデータ構造にすると「テーブル × 回数 × フィールド」を引きやすいか考える
- [ ] 定数が正しく写せているかを確かめるテストを書く（例: 各回の選択率の合計が 100% になるか）
- [ ] 「記録 → 1テーブルの確率」を返す関数のテストを書き、失敗を確認してから実装する
- [ ] 「記録 → 4テーブルの割り振り」を返す関数のテストを書き、実装する
  - 1 で計算した値を期待値にする
  - 境界値: 記録なし／1回目だけ／7回目／あり得ない記録
- [ ] わざと実装を壊して（数値を1つ変えるなど）、テストが失敗することを確かめる

## 3. 記録を保持する hook を作る

- [ ] 必要な操作を決める（例: クエストを追加・最後の結果を変える・1つ戻す・リセット）
- [ ] 「成功したあとは追加できない」「7回目は外れにできない」など、操作のルールを書き出す
- [ ] リロードで消えてほしくないかを決める。保存するなら `useCount(storageKey)` 経由にする（規約）
  - `useCount` は数値しか保存できない。記録（配列）をどう数値で持つか考える
  - storageKey は `mhrise-` で始めて、他の機種と重ならないようにする
- [ ] `renderHook` でテストを書いてから実装する（`beforeEach(() => localStorage.clear())` を忘れずに）

## 4. 画面を作る

- [ ] 画面のラフを描く（入力ボタン・記録の一覧・推測結果）
- [ ] コンポーネントを作り、`MhrisePage.tsx` の「準備中」を差し替える
- [ ] Testing Library でテストを書く: ボタンを押す → 表示される % が 1 で計算した値になる
- [ ] `src/App.test.tsx` の「準備中」を確かめている部分を、新しい画面に合わせて直す

## 5. 仕上げ

- [ ] `npm run check` を通す（カバレッジは `src/machines` も 100% が必要）
- [ ] `npm run dev` で実際に操作して確かめる
- [ ] CLAUDE.md の「構成」の `mhrise/` の説明を実態に合わせる（CLAUDE.md の編集には `.claude/allow-config-edit` が必要）
- [ ] コミットする

## 発展（余裕があれば）

- [ ] 事前確率を均等以外にする（例: リセット時は 75% 以上で天国準備 or 天国）
- [ ] 出典にあるテーブル移行率（設定ごと）を使って、設定推測につなげられるか考える
